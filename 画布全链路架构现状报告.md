## 1. 渲染层逻辑 (Rendering & LOD)

### 1.1 视口剔除机制

#### 核心实现：`useViewportIntersection` Hook

**位置**: `packages/drawnix/src/hooks/use-viewport-intersection.ts`

#### 1.1.1 视口计算逻辑

```typescript
function calculateViewportRectangle(boardInstance: PlaitBoard, paddingValue: number): RectangleClient {
    const viewport = boardInstance.viewport;
    const containerRect = getViewportContainerRect(boardInstance);
    
    // 考虑缩放因子，将屏幕坐标转换为画布坐标
    const zoom = viewport.zoom;
    const viewportWidth = containerRect.width / zoom;
    const viewportHeight = containerRect.height / zoom;
    
    return {
        x: origination[0] - paddingValue,
        y: origination[1] - paddingValue,
        width: viewportWidth + paddingValue * 2,
        height: viewportHeight + paddingValue * 2
    };
}
```

#### 1.1.2 计算频率与触发条件

| 触发场景 | 行为 | 防抖策略 |
|---------|------|---------|
| 缩放 (zoom) 变化 | RAF 检测，变化 > 0.0001 时触发 | 交互期间不更新，只记录变化 |
| 平移 (origination) 变化 | RAF 检测，比较 JSON 序列化字符串 | 交互期间不更新，只记录变化 |
| 交互结束 | 防抖延迟 (recoveryDelay: 300ms) 后触发 | RAF 节流 |
| 画布内容变化 | 通过 board 'change'/'selectionChange' 事件 | RAF 节流 |

#### 1.1.3 视口外渲染内容

**首屏保护延迟**: `boardReadyDelay: 500ms`
- 画布初始化时，所有图片被认为在视口外
- 等待 500ms 后才允许加载图片

**视口外状态** (`!isIntersecting`):
```typescript
// 返回骨架屏占位，而非真正的 img 标签

    return (
        <div style={{ backgroundColor: '#f5f5f5' }}>
            <div className="shimmer-animation" /> {/* 骨架屏动画 */}
        </div>
    );
}
```

#### 写入服务 (`asset-storage-service.ts`)

```typescript
async createAssetFromFile(file: File): Promise<string> {
    const assetId = nanoid();
    const blob = new Blob([await file.arrayBuffer()], { type: file.type });
    
    return this.saveAsset({
        id: assetId,
        type: 'image',
        mimeType: file.type,
        blob,
        size: blob.size
    });
}
```

### 2.3 画布序列化结构

#### CanvasImageItem 类型定义

```typescript
interface CanvasImageItem {
    id: string;           // 元素唯一标识
    assetId: string;      // IndexedDB 资产 ID（持久化）
    url?: string;         // 运行时 blob: URL（内存）
    prompt?: string;      // AI 生成 prompt
    position?: ImagePosition;
    size: ImageSize;
}
```

#### 序列化规则

| 字段 | 是否持久化 | 说明 |
|------|-----------|------|
| `id` | **是** | 画布 JSON 必需 |
| `assetId` | **是** | IndexedDB 索引键 |
| `url` | **否** | 运行时生成，不序列化 |
| `size` | **是** | 宽高信息 |
| `prompt` | **是** | 用户编辑内容 |

**重要**: `url` 字段为运行时属性，`CanvasImageItem` 序列化到 JSON 时不包含 `url`，重新加载时通过 `assetId` 从 IndexedDB 重建。

**迁移流程**:

#### Base64 处理 (migration-service.ts 第 185-213 行)

```typescript
// 如果是 base64，转换为 Blob 并保存
if (imageData.startsWith('data:')) {
    const base64Data = imageData.split(',')[1];
    const binaryString = atob(base64Data);
    const bytes = new Uint8Array(binaryString.length);
    for (let i = 0; i < binaryString.length; i++) {
        bytes[i] = binaryString.charCodeAt(i);
    }
    const blob = new Blob([bytes], { type: 'image/png' });
    
    await assetStorageService.saveAsset({ ..., blob });
}
```

**说明**: 旧文件中的 Base64 图片在迁移时被提取并存储到 IndexedDB，减少画布 JSON 的体积。

#### 3.1.2 事件拦截点

| 事件 | 处理器 | 行为 |
|------|--------|------|
| `pointerDown` | 包装 `board.pointerDown` | 设置 `isInteracting = true` |
| `pointerMove` | 包装 `board.pointerMove` | 设置 `isInteracting = true` |
| `pointerUp` | 包装 `board.pointerUp` | 延迟检查，触发 `scheduleRecovery()` |
| `wheel` (ctrlKey) | `host.addEventListener` | 设置 `isZooming = true` |

#### 3.1.3 React 渲染保护

```typescript
// 缩放期间：冻结当前渲染状态，不切换 src
if (isZooming) {
    renderStateRef.current.isFrozen = true;
    // 不调用 forceUpdate()，避免 React 重渲染
}

// 缩放结束：解除冻结 + 恢复渲染
else {
    renderStateRef.current.isFrozen = false;
    forceUpdate(n => n + 1);  // 只在结束时触发一次
}
```

**关键机制**: `renderStateRef` 绕过 React 状态，在交互期间保持组件不更新。

## 5. 已知问题与待优化项

### 5.1 内存管理

| 问题 | 描述 | 严重程度 |
|------|------|---------|
| 临时 blob: URL 泄漏 | `URL.revokeObjectURL()` 未被调用 | 中 |
| IndexedDB 数据无清理 | `cleanOldAssets()` 存在但未自动调用 | 中 |
| 缩略图缓存无限制 | `thumbnailCache` 可能无限增长 | 低 |

### 5.2 性能边界

| 场景 | 当前策略 | 瓶颈 |
|------|---------|------|
| 海量图片 (100+) | LOD + 视口剔除 + 并发控制 | 首屏加载可能卡顿 |
| 超大图片 (>10MB) | 乐观更新 + 异步存储 | IndexedDB 写入可能失败 |
| 旧文件迁移 | 同步解压 + 批量写入 | 首次加载可能阻塞 |

### 5.3 状态同步

| 问题 | 描述 | 影响 |
|------|------|------|
| `fullImageUrl` 切换 | IndexedDB 加载完成后可能不触发重渲染 | 图片可能仍显示 blob: URL |
| `thumbnailSrc` 覆盖 | 高清图加载完成后缩略图仍可能被使用 | 特定条件下显示模糊 |

## 6. 总结

### 当前架构优势

1. **乐观更新**: 新插入图片立即显示，不等待 IndexedDB
2. **LOD 分级渲染**: 低缩放级别使用缩略图，减少内存占用
3. **视口剔除**: 只渲染可见区域图片，提升首屏性能
4. **事件驱动**: 交互期间冻结渲染，避免 React 渲染风暴
5. **并发控制**: 资产加载队列限制并发，防止 OOM

### 架构待改进

1. **内存管理**: 完善 ObjectURL 和缓存的生命周期管理
2. **状态同步**: 确保 IndexedDB 加载完成后的状态一致性
3. **错误恢复**: 增强加载失败后的重试和降级策略
